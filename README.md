# Dissertation 3 — Tokenized Gold Analysis Pipeline

A reproducible Python analysis project for a dissertation on tokenized gold, gold spot, and gold futures.

**Research focus:** how tightly PAX Gold (`PAXG`) and Tether Gold (`XAUT`) track gold, whether weekday price discovery depends on the benchmark used, and whether weekend token trading contains predictive information about the next gold-market adjustment.

One-line summary of the empirical result: *tokenized gold tracks gold closely in the long run, weekday leadership is benchmark-sensitive rather than robust, and weekend token moves contain predictive information about the following gold-market adjustment.*

---

## 1. Repository scope

This repository is set up as a **code-first** version of the project.

- The Python pipeline lives in `02_data_pull/`, `03_process/`, `04_analyze/`, and `scripts/`.
- Generated data and result files are written to `data/` and `05_results/`.
- Dissertation PDFs, literature files, and local notes are ignored by `.gitignore` so the repo stays focused on code.
- A short execution guide is provided in `REPRODUCTION.md`.

## 3. Data

Two tokenized-gold coins are studied against two gold benchmarks:

| Series | Ticker | Source | Frequency | Sample period | Notes |
|---|---|---|---|---|---|
| Tokenized gold | PAXG | Yahoo Finance | Daily | 26 Sep 2019 – Jul 2026 | Clean, complete |
| Tokenized gold | XAUT | Yahoo Finance | Daily | 7 Feb 2020 – Jul 2026 | Clean, complete |
| Spot gold | XAU/USD | Alpha Vantage | Daily | 1 Jun 2011 – Jul 2026 | Thin weekend quotes → treated as closed at weekends |
| Gold futures | GC=F | Yahoo Finance | Daily (OHLC) | 2 Jan 2018 – Jul 2026 | Genuinely closed at weekends; used for weekend & tradeability tests |

**Why two benchmarks:** spot gold (`XAU/USD`) is the conceptual benchmark because the tokens are claims on physical gold. Gold futures (`GC=F`) provide a more clearly timed exchange benchmark and are especially useful for reopening-gap and timing-sensitive checks.

**Data construction:** raw prices are aligned to a common daily calendar; log prices are taken; the **basis** (token log-price minus gold log-price = the gap between them) is computed; and **weekend "events"** are built — each event pairs the token's Friday→Sunday move with the following Monday's gold move.

## 4. Methods (mapped to the hypotheses)

The methodology runs in the same order as the hypotheses, each building on the last.

| Step | Method | What it answers | Hypothesis |
|---|---|---|---|
| Preliminary | ADF unit-root test | Are the price series non-stationary (do they "wander")? | — |
| Linkage | Engle–Granger cointegration | Do token and gold share a stable long-run relationship? | **H1** |
| Weekday price discovery | VECM + Gonzalo–Granger, **both benchmarks** | When gold is open, does the token lead? | **H2** |
| Weekend prediction | Predictive regression (OLS + HAC) + out-of-sample | Does the weekend token move predict Monday gold? | **H3** |
| *Identification* | **Placebo** (mid-week) + **decay** (Tue/Wed) | Is the effect really caused by the closure? | *H3* |
| Uncertainty transmission | Weekend volatility → magnitude of Monday move | Does the token also predict *how big* the move is? | **H4** |
| Efficiency (discussion) | Reopening gap vs intraday session | How fast is the information impounded? | — |
| Robustness (nulls) | Momentum, asymmetry, liquidity conditioning | Tested; no robust effect | — |

All regressions use **HAC (Newey–West) standard errors** because financial returns are heteroskedastic and autocorrelated; the models are OLS-based but extended to handle non-stationarity (cointegration/VECM) and those error properties (HAC).

## 6. How to run

**Easiest — the whole pipeline in one command** (from this folder):

```bash
bash run_all.sh
```

The runner always executes the daily pipeline. It executes the intraday / hourly robustness block only when these files already exist in `data/raw/`:

- `paxg_yahoo_60m.csv`
- `xaut_yahoo_60m.csv`
- `gc_f_yahoo_60m.csv`

**Or step by step, in order:**

```bash
# 1. Download data (needs internet)
python3 02_data_pull/pull_market_data.py

# 2. Build the weekend-event dataset + weekend prediction summary / asymmetry test (H3, H3b)
python3 scripts/option2_weekend_design.py --asset paxg
python3 scripts/option2_weekend_design.py --asset xaut

# 3. Run the core analyses in order
python3 04_analyze/01_run_vecm_price_discovery.py      # H2 - weekday, BOTH benchmarks
python3 04_analyze/02_run_design_hypotheses.py         # H1 + H3
python3 04_analyze/03_run_weekend_marginal_contribution.py
python3 04_analyze/04_run_oos_precision.py
python3 04_analyze/05_run_monday_gap_robustness.py
python3 04_analyze/06_run_trading_strategy.py          # efficiency (impounding speed)
python3 04_analyze/07_run_oos_filter.py
python3 04_analyze/08_run_volatility_momentum.py       # H4 + momentum null
python3 04_analyze/09_run_liquidity_conditioning.py    # liquidity null
python3 04_analyze/10_run_placebo_decay.py             # H3 identification
python3 04_analyze/13_run_placebo_weekend_interaction.py
python3 04_analyze/14_plot_h3_prediction.py
python3 04_analyze/plot_benchmark_reversal.py
```

**Optional — intraday / hourly robustness block**

```bash
python3 03_process/02_build_intraday_reopen_events.py --asset paxg --token-source yahoo --benchmark gc_f_yahoo
python3 03_process/02_build_intraday_reopen_events.py --asset xaut --token-source yahoo --benchmark gc_f_yahoo
python3 04_analyze/11_run_intraday_reopen_regression.py --token-source yahoo --benchmark gc_f_yahoo
python3 04_analyze/12_run_intraday_sensitivity.py --token-source yahoo --benchmark gc_f_yahoo
python3 04_analyze/13_run_hourly_volatility_robustness.py
```

All outputs land in `05_results/`.

## 7. How to read the results

Two numbers unlock every table:

- **Beta (β)** = the **size** of the effect (e.g. weekend β = 0.6 means gold moves 0.6 for every 1 the token moves).
- **t (t-statistic)** = how much you can **trust** it. Rule of thumb: **|t| > ~2 → real; below 2 → indistinguishable from zero.** Bigger t = more confident.

The one number to look at per analysis:

| Script | Question | Number to read | Result |
|---|---|---|---|
| `01_run_vecm_price_discovery` | Which market leads on weekdays? | `token_gonzalo_granger_share`, **both benchmarks** | spot 0.62/0.80 vs futures 0.28/0.41 → **benchmark-sensitive** |
| `option2` / `02_run_design_hypotheses` | Does weekend predict Monday? | weekend beta `t_stat_hac` | 4.3 / 7.3 → **significant** |
| `10_run_placebo_decay` | Is it caused by the closure? | placebo vs weekend beta; Tuesday t | weekend effect is much larger; Tuesday effect fades out |
| `08_run_volatility_momentum` | Does it predict move *size*? | `weekend_rv_t` | XAUT 3.09 ✅ / PAXG 1.92 (marginal) |
| `08` (momentum) | Does momentum add anything? | `momentum_5_t`, `momentum_20_t` | inconsistent → **null** |
| `09_run_liquidity_conditioning` | Does more liquidity strengthen it? | interaction t | measures disagree → **null** |
| `03_run_weekend_marginal_contribution` | Real info or just the gap closing? | partial R² (≈ 0.22) | adds real info beyond the basis |
| `04_run_oos_precision` | Holds out-of-sample? | OOS hit rate | > 50% → not a fluke |
| `05_run_monday_gap_robustness` | Robust on futures? | weekend beta / t | significant (t 2.2–9.2) |
| `06_run_trading_strategy` / `07_run_oos_filter` | How fast is it impounded? | gap vs intraday returns | concentrated in the **reopening gap** |

Key summary files in `05_results/`:

- `vecm_price_discovery_summary.md` — who leads (H2)
- `design_hypotheses_summary.md` — linkage + weekend prediction (H1, H3)
- `weekend_marginal_contribution_summary.md` — the signal's own share
- `oos_precision_summary.md` — out-of-sample precision
- `monday_gap_robustness_summary.md` — robustness
- `trading_strategy_summary.md` — economic significance (H4)
- `HOW TO READ MY RESULTS.md` and `final_results_interpretation.md` — plain-English interpretation

## 9. Interpretation arc

The empirical story runs in one sequence:

1. The tokens are closely linked to gold in the long run.
2. Weekday price-discovery conclusions are sensitive to which benchmark is used.
3. Weekend token moves contain predictive information about the next gold-market adjustment.
4. That predictive content appears strongest when the traditional market is less able to adjust immediately.

That is why the pipeline is ordered the way it is: each stage gives context for the next one.
